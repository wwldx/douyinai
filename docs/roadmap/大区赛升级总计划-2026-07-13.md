## 3. 取舍原则

### 3.1 评分维度

每项升级按 1 到 5 分评估：

| 维度 | 权重 | 判断问题 |
|---|---:|---|
| 官方评分对齐 | 25% | 能否直接增强五个官方评分项之一？ |
| 评委/观众吸引力 | 20% | 15 秒内是否可见、可理解、可记住？ |
| Solo 可完成性 | 20% | 用户一个人能否在截止前完成并维护？ |
| 稳定性收益 | 15% | 是否降低公网、模型、现场或操作失败风险？ |
| 算法证据价值 | 15% | 是否能产生评测、消融、失败案例或可解释方法？ |
| 秋招复用价值 | 5% | 能否形成可信的多模态算法项目增量？ |

硬性交付不受总分影响，直接进入 P0。任何升级如果没有清晰验收条件，即使看起来先进，也不得进入开发。

### 3.2 状态定义

| 状态 | 含义 |
|---|---|
| Candidate | 已记录，尚未批准开发 |
| Approved | 已确认进入当前版本 |
| In progress | 正在开发，Solo 同时最多一项 |
| Verified | 已通过验收并有证据 |
| Frozen | 比赛前冻结，只修 P0 缺陷 |
| Deferred | 有价值但本次不做 |

## 5. 当前推荐版本

### 5.1 必须形成的获奖闭环

```text
抖音 Feed 刷到想吃的菜
-> 暂停帧/菜图触发
-> 语音或文本补充“只有 25 分钟”
-> 拍冰箱并确认库存
-> 检索相似成功/失败 case
-> Agent 判断今晚照做、简化、补买或延期
-> 用户反馈是否解决
-> 缺料时商城补齐，做好后内容回流
```

这条链同时覆盖：真实场景、多模态必要性、抖音生态、AI Workflow、满足判断和增长闭环。

U15 的确定性白名单规则和 12 例回归继续保留，但 2026-07-16 已从主展示撤回“用户先选一种关键食材”的步骤及附加结果卡。原因是后续本来就要拍冰箱并确认库存，单项选择重复且没有真正改变主规划。若未来重新启用，只允许改为整道菜所需材料与确认库存的后台自动比较，不再增加用户选择步骤。

U16 已将“冰箱救援 -> 本餐行动”具体化：用户在确认库存后可选填已开封、确认标签日期临近或状态不确定，确定性规则输出本餐优先、近两餐和待确认三组，并把最多 5 个优先食材传入 Planner。10 例规则回归、发布冒烟、真实模型规划和 390px 布局均通过；规则不读取图片日期，也不输出过期或安全食用结论。

U17 已完成：`/api/fridge-organization` 将现有视觉 `notes` 确定性归一化为 `door / top / middle / bottom / crisper / freezer / unknown`，输出最多三条建议。18 例规则回归、发布冒烟、真实规划结果页、开发检验台和 390px 布局均通过；歧义分区输出 `unknown`，跨区建议要求用户确认包装条件，且不输出食品安全结论。

U18 已完成：结果页可切换“现在 / 建议后”，只应用 U17 中已经满足前提的移动建议，`confirm_first` 保持原位。18 例规则回归同时核对同区前移、跨区移动和未确认保持原位；桌面与 390px 交互通过。它是建议效果预览，不宣称用户已完成整理，也不通过二次照片判断安全结果。

U10 已完成本地端到端：结果页可拍摄、从相册选择或加载示例成品图，生成并编辑标题、封面文案、旁白、补拍镜头和标签；开发检验台同步展示原始请求、结果、来源和耗时。确定性草稿回归、发布冒烟、桌面和 390px 布局均通过。2026-07-18 的 terra 定向样例返回 `source=model`，约 26.65 秒、3,228 tokens，门禁通过；它只有一个固定成品图样例，不代表真实用户照片泛化。该功能不接入真实发布权限，不把图片无法证明的口感、营养、过程、播放量或反馈写成事实。

U02 已于 2026-07-18 用当前 `gpt-5.6-terra` 完成固定 30 例真实模型基线：30/30 通过，11 例视觉与 19 例规划全部为 `source=model`，Schema、规划动作与禁用语义门禁均为 100%；平均 18.33 秒、P95 28.03 秒，总 114,467 tokens。视觉输入按展示端规则压缩到最长边 1400px JPEG；评测同时记录确认召回与“确认 + 明确不确定”覆盖，避免鼓励模型硬猜。原“黄焖鸡”素材实际是干锅鸡块，已换成内容相符的无文字示例图；两条过度确定的旧缓存真值也按图片证据校正。该结果只代表固定回归集，不代表真实用户准确率。

### 5.1.3 2026-07-17 009 可观测与可信降级

009 增加隐私受控的 `agent_runs` 运行记录，不再依赖容器临时文件判断公网请求发生了什么：

1. 每次 Agent 请求携带匿名会话 ID 和客户端生成的请求 ID；即使前端在 60 秒主动停止等待，内部记录也能以同一诊断编号标记 `client-disconnect / 499`，用于区分模型慢、服务错误和客户端超时。
2. 默认只保存路由、状态、来源、Agent、模型、阶段耗时、token usage、输入输出数量摘要和错误码，保留 7 天；不保存照片、录音、转写原文、文件名、API Key、鉴权头或自由描述。只有显式开启 `AGENT_RUNS_CAPTURE_CONTENT=true` 才保存经过字段白名单与媒体过滤的结构化库存/方案，用于赛前受控调试。
3. 记录写入失败采用 fail-open：只更新健康状态和脱敏错误码，不阻断用户的识别、规划或救援主流程。CloudBase 运行期不默认创建集合，部署前由管理员预建 `agent_runs`，服务只持有必要的数据读写权限。
4. `/ops.html` 是内部运维台，数据接口必须使用至少 24 位的 Bearer 管理员令牌；令牌只保存在当前浏览器标签的 `sessionStorage`，页面不进入主演示导航。它展示的是当前真实运行证据，不是虚构用户量、PV 或抖音画像后台。

结果页保留可信降级提示，但不再把 `model-timeout-cache` 等内部标识直接抛给用户：实时成功弱提示“已根据本次库存生成”，超时或服务波动才明显提示“已切换稳定方案”，精确 provider、source、耗时和诊断信息留在运维台。比赛最终版不应删除这条诚实边界，否则固定兜底又会被误认为实时模型结果。

本地定向验收已确认：请求 ID 前后端一致；未带令牌访问返回 401；带令牌可读取记录；注入的 `imageDataUrl` 和 `transcript` 字段被过滤；清理接口可删除记录；React 生产构建通过。009/010 公网又完成 CloudBase 集合实际写入、管理员鉴权查询、`/ops.html` 同诊断编号检索、结构化内容边界和 fail-open 验收，因此 U33 已 Verified。011 本地浏览器服务显式关闭 `agent_runs`，该报告不能冒充 011 的云端持久化证据；部署后仍需一次定向复验。

> [可讲] 我们没有把模型失败藏起来：用户看到可继续操作的稳定方案，内部则用同一个诊断编号记录模型来源、阶段耗时和失败位置。照片和录音不进运行记录，默认只保存最小必要元数据。

### 5.2 界面升级方向

初赛界面可以作为工程基线，但不能作为大区赛最终视觉。大区赛版本需要：

- 首屏直接呈现真实菜品或冰箱画面，不做说明型落地页。
- 首屏提供“从 Feed 刷到想吃的”和“打开冰箱不知道吃什么”两个场景入口。
- 主演示默认走 Feed 路线，避免被理解成普通冰箱菜谱。
- 使用移动优先的内容浏览节奏，减少卡片堆叠和后台术语。
- 保留白色/炭黑信息底色，以番茄红、香草绿和蛋黄黄作有限状态色，不做单一色主题。
- 使用真实食物与冰箱图片作为第一视觉信号；图标只服务操作，不承担主视觉。
- 等待状态、库存确认、缺料结果和最终行动必须一眼区分。
- 结果页加入明确反馈，展示 Agent 会根据“太麻烦/缺料多/不想洗锅”调整方案。

界面验收：

- 390×844 和 1440×900 均无横向溢出、遮挡和文本裁切。
- 评委进入后 15 秒内能说清“刷到菜，回家看冰箱能不能做”。
- 第一个可操作入口在首屏内。
- 不展示 provider、模型名、JSON、缓存路径和内部画像字段。
- 真实模型、缓存和失败来源在开发检验台可审计。

## 6. 算法部分的边界

### 6.1 本次做什么

本次算法增强采用 FinFRE-RAG 类似的低资源路线：

```text
结构化场景表示
-> 检索相似历史 case
-> 选择成功与失败对照例
-> 作为受控上下文输入规划 Agent
-> 输出严格 Schema
-> 满意度反馈与离线评测
```

它的价值不是让架构显得复杂，而是回答三个可验证问题：

1. 相似 case 能否减少缺关键主料却声称可做的错误？
2. 正反例对照能否提高路线选择和解释的一致性？
3. 增益是否值得额外延迟和 token 成本？

### 6.2 本次不做什么

OneReason 的完整链路是多粒度预训练、结构化 CoT SFT、分领域 GRPO，再通过 RFT 或 MOPD 统一。这需要大规模数据、训练资源、reward、teacher 和长期实验，不是本次 Solo 比赛的合理范围。

因此不得对外声称：

- 复现 OneReason。
- 完成 GRPO、RFT、MOPD 或在线蒸馏。
- 训练出领域模型或 teacher。
- 历史 case 检索提升了规划指标；当前真实消融中 `positive` 与 `off` 同为 19/19但 token 增加 19.2%，`contrast` 为 18/19、token 增加 24.1%且出现动作退化。
