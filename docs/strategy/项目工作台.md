## 4. 当前工作原则

- 先做闭环，不先做复杂架构。
- 先服务一个具体人群和具体时刻，不做泛 AI 助手。
- 先准备稳定 demo，再补充视觉包装。
- 技术文档必须显式对齐评分表，方便评委快速给分。
- 对外展示采用「情景视频 -> 用户端 Demo -> 开发检验台」三层结构：先让观众理解用户痛点，再展示真实操作，最后用后台链路证明系统可信。可复用方法论见 `docs/strategy/AI_Agent情景化Demo展示工作流.md`。
- 本次比赛形成的跨项目复用经验已汇总到 `总结经验/`：以后启动新 Agent 项目时，可以整体复制该目录，让协作 Agent 先阅读 `README.md` 与 `00_给未来Agent的启动提示词.md` 再进入选题和开发。

## 5. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 选题过泛 | 评委难以判断用户价值 | 用单一场景约束用户、触发时刻和结果 |
| 模型接口不稳定 | 现场 demo 失败 | 准备固定样例、缓存结果、录屏 |
| 游园会解释成本高 | 大众票和互评票受损 | 海报只讲一个场景、一张结果图、一个二维码 |
| 只做聊天入口 | 和普通 AI 助手差异弱 | 增加主动触发、视觉输入、个性化状态或可分享输出 |
| 文档和评分点脱节 | 作品优势无法转化为分数 | 在作品说明里单独列评分点对齐表 |
