# 公网部署与回滚计划

更新日期：2026-07-23
状态：CloudBase 012 是当前公网基线，第三轮新前端、严格公网冒烟、静态资源一致性与一次真实目标菜规划已通过；011 保留为首选回滚，待 012 iPhone/抖音内置浏览器真机验收
目标：使用一个 HTTPS 公网域名承载 React H5、示例资源和 Node API，供现场及非现场评委体验

## 1. 部署原则

- 只部署一个容器服务，不拆前后端。
- API Key 只保存在平台 Secret，不进入前端、镜像、日志或 Git。
- 先部署 staging，再确认是否作为最终提交地址。
- 固定示例和缓存是故障兜底，不能冒充实时模型结果。
- 公网版本必须可回滚到上一个已验证镜像或 commit。
- 7 月 23 日后只修 P0，不在现场临时改架构。

### D4：公网加固

上线最终地址前补齐。以下代码侧能力已在本地生产模式完成，公网只需复验阈值、代理和文件系统：

- 对模型 POST API 做可配置的按 IP 限流，超限返回 429。
- 保留 12MB 请求体上限，并在前端继续压缩图片。
- 日志不得记录 base64 图片、音频、完整用户输入、Key 或上游鉴权头。
- 生产健康检查不泄漏上游 endpoint。
- 为每个请求记录 request ID、端点、状态和阶段耗时。
- 用户目录写入失败不得阻断视觉和规划主流程；反馈写入失败时展示端仍保留本次会话约束。
- 平台文件系统只读或临时时可设置 `DATA_DIR` 指向可写挂载目录；它只承载 `local-users`，演示种子、视觉缓存和 Case 库仍随镜像只读发布。

`agent_runs` 不写容器文件系统。CloudBase 文档型数据库集合 `agent_runs` 已完成公网实际写入和管理员查询验收；浏览器客户端仍禁止直接读写，运行服务默认不申请建集合权限。写入失败保持 fail-open，不阻断识别、规划或救援主流程。

内部查询入口为 `/ops.html`。静态页面本身不含数据和令牌，`/api/admin/agent-runs` 未配置管理员令牌时返回 404，令牌错误返回 401。比赛调试阶段保持 `AGENT_RUNS_CAPTURE_CONTENT=true`，保存排障所需的白名单结构化库存、目标文字和规划结果；照片、原始音频、API Key、管理员令牌和鉴权头仍不得保存。

本地默认窗口为 60 秒、普通 API 80 次、模型 API 30 次；这些是保护性初值，不是已验证 QPS。公网压测后通过 `API_RATE_LIMIT_WINDOW_MS`、`API_RATE_LIMIT_MAX`、`MODEL_RATE_LIMIT_MAX` 调整；只有平台反向代理可信时才设置 `TRUST_PROXY=true`。

### D5：外部验收

部署完成后先运行自动冒烟：


该命令检查展示端、开发检验台、健康状态、安全头、Case Top-K 和错误脱敏；它不替代四个真实模型端点、真机权限和完整 30 例评测。

至少从以下环境测试：

- 手机移动网络。
- 电脑无痕窗口。
- Edge 或 Chrome 桌面端。
- 一台没有本地缓存的设备。

测试路径：

1. 固定示例完整流程。
2. 真实冰箱图完整流程。
3. 真实目标菜图完整流程。
4. 拒绝麦克风权限后改用文本。
5. 允许麦克风权限后验证语音。
6. 模型接口失败时验证缓存或错误提示。
7. 连续重新规划和重新上传。

退出条件：非开发者无需本机文件和说明即可完成体验。

## 5. 回滚方案

### 5.1 代码回滚

- 每次部署使用可追踪 commit 或镜像 tag。
- 保留最近一个通过外部验收的版本。
- 新版本失败时切回旧版本，不在生产容器内手工改文件。

### 5.2 模型回滚

- 模型通过 `OPENAI_MODEL` 配置切换。
- 新模型只有在同一评测集上 Schema、安全和关键缺料指标不下降时才能替换。
- provider 故障时回到已验证模型或固定示例缓存。

### 5.3 现场回滚

按优先顺序准备三套路径：

1. 公网真实模型。
2. 公网/本地固定示例缓存。
3. 备用录屏和静态结果截图。

三套路径必须使用同一故事和界面，避免现场切换后讲解逻辑变化。

### 5.4 2026-07-19 实际回滚彩排

1. 基线 011：控制台显示 100% 流量、实例数 1；公网首页与 `/api/health` 为 200，`appVersion=011`、三任务路由 terra、Case 检索 off、`agentRuns.state=ready`。
2. 011→010：控制台执行版本回退；切换窗口内第一次 health 请求在 20 秒无响应后超时，随后 health 为 200、`appVersion=010`、三任务路由 terra、Case 检索 off，首页为 200。010 新实例的 `agentRuns.state=configured` 且无写入错误；本轮没有发送模型或持久化测试请求。
3. 010→011：控制台再次执行版本回退；health 与首页均为 200，恢复 `appVersion=011`、三任务路由 terra、Case 检索 off、`agentRuns.state=ready`。
4. 最终状态：控制台确认 011 为 100% 流量、实例数 1，010 为 0 流量且继续保留；服务级实例配置仍为最小/最大 `1/1`。

结论：版本级回滚路径可用，010 可作为首选应急回滚点；流量切换期间存在短时不可用风险，现场不能把它讲成无缝切换。整个彩排只做首页和严格 health，没有重跑 30 例或调用模型。
