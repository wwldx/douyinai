# 冰箱晚餐 Agent

更新日期：2026-05-23  
推荐赛道：赛道 2，视觉搜索：视觉 + 语音，所见即所想  
当前阶段：方向确认与 MVP 规划  
默认模型策略：优先使用 GPT / Claude 高阶视觉模型

## 1. 一句话定位

拍一下冰箱，AI 根据现有食材、用户口味、厨艺水平和今晚可用时间，推荐最现实的一顿饭。

## 2. 方向来源

原先的赛道 2 方案是“活动海报行动卡”，优点是稳定、易闭环，但容易被质疑成 OCR 套壳，视觉冲击和产品想象力不足。

新的方向把视觉识别从“识别文字”升级成“识别真实生活场景并做决策”：

- 用户拍一张冰箱照片。
- AI 识别冰箱里的食材、饮料、速食和调料线索。
- 系统结合用户历史吃饭记录、偏好、厨艺水平和可用时间。
- 最终判断今晚适合自己做、补买一点再做，还是直接外卖。

这个方向更像一个完整的生活 Agent，而不是单点识别工具。

## 3. 核心价值

用户真正的问题不是“不知道冰箱里有什么”，而是：

- 今晚到底吃什么。
- 这些东西能不能凑出一顿满意的饭。
- 当前时间和精力是否适合做饭。
- 自己的厨艺能不能完成这道菜。
- 缺一点材料时，是补买、换菜，还是点外卖更现实。

产品要解决的是“从冰箱状态到晚餐决策”的问题。

## 4. 为什么比海报方向更有亮点

| 维度 | 海报行动卡 | 冰箱晚餐 Agent |
|---|---|---|
| 视觉输入 | 海报文字和版面 | 真实冰箱、食材、包装、遮挡 |
| AI 作用 | 信息抽取 + 推荐 | 视觉识别 + 个性化决策 + 约束规划 |
| 用户价值 | 判断活动是否值得去 | 直接解决今晚吃什么 |
| 现场互动 | 稳，但容易像 OCR | 更生活化，更容易引发讨论 |
| 商业延展 | 活动报名、日程、转发 | 生鲜、外卖、厨具、饮食管理 |
| 风险 | 创新性不足 | 识别不准、链路较长 |

当前判断：冰箱晚餐 Agent 更有产品想象力，但必须控制 MVP 范围。

## 5. MVP 边界

MVP 不做完整家庭饮食管理平台，只做一个清晰闭环：

```text
拍冰箱
  -> 识别食材
  -> 用户轻量确认
  -> 结合厨艺/偏好/时间
  -> 推荐今晚一顿饭
  -> 给出保底菜、进阶菜、缺料购物清单
```

当前不做：

- 长期营养健康诊断。
- 精准热量估算。
- 真实外卖平台下单。
- 真实生鲜电商购买。
- 复杂家庭多人偏好协调。
- 高风险烹饪动作推荐。

## 6. 核心演示路径

30 秒演示：

1. 用户上传或选择一张冰箱照片。
2. AI 识别出番茄、鸡蛋、黄瓜、牛奶、速冻饺子等。
3. 用户快速确认识别结果。
4. 系统读取模拟用户画像：
   - 新手厨艺。
   - 今晚只有 25 分钟。
   - 偏好少油、不要太辣。
   - 最近两天已经吃过外卖。
5. AI 推荐：
   - 保底：番茄鸡蛋面。
   - 进阶：黄瓜鸡蛋拌面。
   - 缺料升级：补买一把青菜和一袋面条。
   - 如果时间不足：直接煮速冻饺子，不建议复杂炒菜。
6. 输出步骤、耗时、难度、安全提醒和购物清单。

## 7. 赛道表达

不要把它讲成“冰箱识别工具”，而要讲成：

> 一个从所见食材出发，综合用户状态做晚餐决策的视觉 Agent。

对齐赛道 2：

- 触发来自视觉输入：拍冰箱。
- AI 理解现实场景：识别食材、包装、可用材料。
- 结果不是描述图片，而是生成下一步行动。
- 可支持语音追问：“我只有 15 分钟怎么办？”“我不想刷锅怎么办？”“还缺什么？”

## 8. 当前结论

这个方向可行，且比海报方向更有亮点。主要风险是食材识别不稳定和功能链路过长。

正确做法是：

- Demo 使用容易识别、摆放清楚、颜色明显的食材。
- 设计“用户确认食材”步骤，承认视觉识别不是百分百准确。
- 只围绕“今晚吃什么”做闭环。
- 做饭建议必须考虑厨艺、安全、时间和用户偏好。
- 商业化延展可以讲，但不要在 MVP 里做真实交易。
