# 讨论存档

更新日期：2026-05-23  
主题：从海报视觉助手转向冰箱晚餐 Agent

## 1. 起点：赛道 2 的海报方向争议

最初赛道 2 规划为“活动海报视觉助手”：用户上传活动海报，AI 识别时间、地点、报名方式，并生成是否值得参加、日程提醒和转发文案。

这个方向的优点：

- 稳定。
- 可控。
- 适合 OCR 和结构化抽取。
- 现场容易准备缓存样例。

但也存在明显问题：

- 容易被理解成文字识别。
- 亮点不够强。
- 视觉搜索的想象空间没有完全打出来。
- 评委可能会认为只是 OCR 加一层文案。

因此需要寻找一个更有“视觉输入驱动决策”味道的方向。

## 2. 新想法：拍冰箱决定今晚吃什么

新方向来自这样的场景：

用户拍一张家里冰箱里的照片，AI 先识别里面有什么菜、饮料、速食和调料，然后结合用户历史吃饭记录、口味偏好、厨艺水平、下班/放学时间和今晚可支配时间，判断今晚该怎么吃。

核心不只是识别食材，而是决策：

- 现有材料能不能做出满意的一顿饭。
- 用户厨艺是否适合这道菜。
- 时间是否允许。
- 是否需要补买一点材料。
- 是否应该直接外卖或速食兜底。
- 是否可以给出长期厨具升级建议。

## 3. 对可行性的判断

这个方向可行，而且比海报更有产品想象力。

原因：

- 视觉输入更真实，有遮挡、包装、食材状态等复杂信息。
- 推荐结果直接影响用户今晚行动。
- 个性化因素明确，包括厨艺、偏好、时间、历史饮食。
- 可以自然衔接生鲜、外卖、厨具等商业场景。
- 现场演示更生活化，评委更容易产生讨论。

但风险也更高：

- 冰箱识别容易不准。
- 食材新鲜度不能可靠判断。
- 菜谱推荐可能不符合用户厨艺。
- 功能容易发散成完整饮食平台。
- 商业推荐如果表达不好，容易像硬带货。

## 4. Demo 食材策略

为了提高现场成功率，Demo 应使用容易识别的冰箱图。

推荐使用：

- 番茄。
- 鸡蛋。
- 黄瓜。
- 生菜。
- 胡萝卜。
- 牛奶。
- 酸奶。
- 可乐。
- 面包。
- 火腿肠。
- 速冻饺子。
- 面条。
- 鸡胸肉包装。

避免使用：

- 保鲜盒里的剩菜。
- 被遮挡的袋装食材。
- 散装肉类。
- 光线太暗的冰箱。
- 容易引发新鲜度争议的食材。

关键设计：

> 不假装模型能完美识别，而是让 AI 先识别，再让用户 3 秒确认。

这个交互更真实，也能降低模型误判对结果的影响。

## 5. 厨艺和安全边界

这个方向必须考虑用户本身做饭水平。

示例原则：

- 新手不推荐油炸。
- 新手不推荐复杂刀工。
- 新手不推荐处理整鱼、整鸡、硬壳海鲜等高风险食材。
- 晚上下班很晚时，不推荐煲汤、炖肉等长耗时菜。
- 低精力状态下，推荐简单热食、速食或外卖兜底。
- 食材新鲜度必须提醒用户自行确认。

这不是细节，而是产品可信度的一部分。

## 6. 商业延展的表达方式

原始想法里提到可以通过推荐用户买空气炸锅等方式增加额外消费。

这个方向可以保留，但表达要克制。

不建议说：

> 勾引用户消费。

建议说：

> 在用户真实晚餐决策中，自然衔接生鲜补货、外卖兜底和厨具升级建议。

空气炸锅示例：

> 如果用户近期多次想做低油炸物，但总反馈油烟大、失败率高，可以温和建议空气炸锅；如果只是偶尔一次，就不推荐购买。

这样更像负责任的 AI Agent，而不是硬广告。

## 7. 最终收敛

当前方向不做“大而全家庭饮食管理”，只做：

> 冰箱晚餐 Agent：拍一下冰箱，帮你决定今晚吃什么。

MVP 最小闭环：

```text
冰箱图片识别食材
  -> 用户确认库存
  -> 结合厨艺/时间/偏好
  -> 推荐一道保底菜
  -> 推荐一道进阶菜
  -> 给出缺料购物清单或外卖兜底
```

当前优先级：

1. 做出静态样例闭环。
2. 准备清晰冰箱图。
3. 接入 GPT / Claude 视觉模型。
4. 保留缓存 JSON 兜底。
5. 再考虑商业延展展示。
