# 比赛现场上游规划自检

## 最快使用方式

先保证本地服务运行在 `http://127.0.0.1:4183`，然后在 Finder 中双击：

```text
scripts/比赛现场-检查上游规划.command
```

脚本会依次检查：

1. 本地服务是否启动；
2. 服务端是否读取到 API Key；
3. 当前 provider、规划模型和规划超时；
4. 使用一份固定的「黄焖鸡、冰箱材料已齐」数据真实调用 `/api/plan-target-dish`；
5. 输出耗时、HTTP 状态、错误码、Request ID、执行菜名、步骤数量和材料判断。

脚本不会读取、打印或保存 API Key，也不上传照片。完整的结构化报告保存到本机忽略目录：

```text
data/local-cache/upstream-planning-smoke-latest.json
```

## 终端运行

```bash
npm run smoke:upstream-plan
```

检查指定的公网版本：

```bash
npm run smoke:upstream-plan -- "https://你的部署域名"
```

只检查脚本和固定请求，不访问真实模型：

```bash
npm run smoke:upstream-plan -- --dry-run
```

## 结果解释

- `MODEL_CONNECT_ERROR`：服务已自动尝试两次连接但仍未连通，不是 50 秒模型业务超时。
- `MODEL_TIMEOUT` / HTTP 504：模型超过约 50 秒仍未完成。
- `MODEL_SERVICE_UNAVAILABLE` / HTTP 502、503：上游暂时不可用，可原样重试。
- `MODEL_RESPONSE_INVALID`：模型有响应，但结构化结果没有通过契约检查。
- HTTP 200 但最终显示警告：网络和模型已响应，但「材料已齐」业务语义没有全部通过，需要查看报告中的 `checks`。

该脚本会真实调用一次规划模型并产生对应 token，只在需要检查上游时运行。
