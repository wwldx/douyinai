# 冰箱晚餐 Agent 双路线演示操作文档

更新日期：2026-05-23  
适用对象：队友、现场演示人员、开发调试人员

## 1. 当前界面为什么有三个按钮

当前展示页有三个核心按钮：

```text
识别冰箱
生成晚餐方案
判断复刻路线
```

它们不是三条并列路线，而是：

```text
识别冰箱 = 两条路线共同前置步骤
生成晚餐方案 = 用户不知道吃什么时，让 AI 帮忙决定
判断复刻路线 = 用户已经想吃某道菜时，判断今晚能不能复刻
```

一句话理解：

```text
识别冰箱 = 看现实
生成晚餐方案 = 不知道吃什么时，AI 帮你决定
判断复刻路线 = 已经刷到想吃的时，AI 判断能不能做、缺什么、怎么补
```

## 3. 共同前置步骤

两条演示路线都先走同一段：

```text
上传冰箱图片
  -> 点击「识别冰箱」
  -> 在「识别库存」里人工确认食材
```

操作步骤：

1. 打开展示页 `http://localhost:4174/`。
2. 在左侧上传区域选择冰箱图片。
3. 点击「识别冰箱」。
4. 等待视觉识别结果返回。
5. 在「识别库存」区域确认食材。
6. 可以取消勾选一两个不确定项，用来展示人工确认和安全边界。

这一步对应接口：

```text
POST /api/analyze-fridge
```

现场讲法：

```text
AI 先看见冰箱里的现实库存，但不会假装自己能判断所有食材都一定新鲜，所以中间保留人工确认。
```

## 4. 路线 A：不知道吃什么

适用场景：

```text
用户打开冰箱，但不知道今晚吃什么。
```

操作步骤：

1. 完成共同前置步骤。
2. 点击「生成晚餐方案」。
3. 查看右侧结果：
   - 本次参考依据
   - 保底方案
   - 进阶一点
   - 缺料补买
   - 外卖 / 速食兜底
   - 安全提醒
   - 商业延展

这一步对应接口：

```text
POST /api/plan-dinner
```

现场讲法：

```text
当用户没有明确想吃什么时，AI 会根据冰箱库存、厨艺水平、时间、精力和用户画像，给出今晚最现实的一顿饭。
```

更短讲法：

```text
这条路线解决的是“我不知道吃什么”。
```

## 5. 路线 B：刷到想吃的

适用场景：

```text
用户在抖音刷到一道想吃的菜，想知道自己家冰箱今晚能不能复刻。
```

操作步骤：

1. 完成共同前置步骤。
2. 在「刷到想吃的」区域可以二选一：

```text
方式 1：直接输入目标菜文字。
方式 2：上传想复刻的菜图，点击「识别目标菜」，让 AI 先猜菜名和关键材料。
```

3. 如果用文字输入，可以写：

```text
我今晚想吃番茄牛腩
```

4. 如果上传了目标菜图，页面会显示：

```text
AI 猜测菜名
关键材料
可能工具
预计耗时
难度提醒
```

识别后会自动把菜名写入输入框，但用户仍然可以手动修改。这样即使模型猜错，流程也不会失控。

5. 选择目标时间：
   - 今晚
   - 明天
   - 这周
6. 点击「判断复刻路线」。
7. 查看右侧「目标菜复刻」结果：
   - 能不能尽量复刻
   - 冰箱已有材料
   - 关键缺口
   - 可选缺口
   - 替代路线
   - 可执行路线
   - 难点提醒
   - 抖音商城 / 本地生活模拟补齐卡

这一步对应接口：

```text
POST /api/analyze-target-dish
POST /api/plan-target-dish
```

现场讲法：

```text
普通聊天机器人可以告诉你番茄牛腩怎么做，但这里会先看你家的冰箱、今晚时间和厨艺水平，判断现在能不能复刻；如果不能，就给你简化版本、明天补买路线和抖音生态里的模拟补齐卡。
```

更短讲法：

```text
这条路线解决的是“我刷到想吃的，今晚能不能做”。
```

## 6. 推荐现场演示顺序

推荐先展示路线 B，再展示路线 A。

原因：

```text
路线 B 更能体现抖音差异化：
内容种草 -> 冰箱现实检查 -> 缺料补齐 -> 商城 / 本地生活模拟卡
```

完整顺序：

1. 开场讲故事：

```text
普通聊天机器人能回答菜谱，但抖音场景更自然的是：刷到想吃的，拍下冰箱，看看今晚能不能复刻。
```

2. 上传冰箱图。
3. 点击「识别冰箱」。
4. 人工确认库存。
5. 输入目标菜，例如「我今晚想吃番茄牛腩」。
6. 如果有目标菜图，可以先上传菜图并点击「识别目标菜」。
7. 点击「判断复刻路线」。
8. 展示目标菜复刻结果和抖音商城 / 本地生活模拟卡。
9. 再点击「生成晚餐方案」。
10. 说明如果用户没有明确目标菜，AI 也能直接规划今晚饭。

## 6.1 为什么暂不做多图自动分类

当前 V2 采用两个明确上传区：

```text
上传冰箱照片
上传想复刻的菜图
```

暂不支持一次上传多张图后自动判断哪张是冰箱、哪张是目标菜。

原因：

```text
现场演示需要稳定。自动分类一旦把菜图当成冰箱，或把冰箱图当成目标菜，解释成本会很高。
```

多图自动分类先放进后续规划：

```text
V2.5：一次上传多张图 -> AI 自动分类 -> 用户确认分类 -> 再进入识别流程
```

## 7. 不展示可做指数的原因

目标菜复刻路线不展示 `42/100` 这类可做指数。

原因：

```text
现场不好解释分数怎么计算，容易把注意力带偏。
```

当前展示方式改成：

```text
尽量复刻路线
难点提醒
简化版本
补买 / 明日准备建议
```

现场讲法：

```text
我们不把复杂生活决策压成一个分数，而是直接告诉用户现在怎么做更稳。
```

## 8. 商城 / 本地生活模拟卡怎么讲

商业卡不是硬广，只在这些情况下出现：

```text
缺关键材料
缺关键工具
时间太晚或食材风险高，需要本地生活 / 外卖兜底
```

例如：

```text
目标菜：番茄牛腩
冰箱已有：番茄、鸡蛋、面条
关键缺口：牛腩、土豆
模拟卡：牛腩 + 土豆组合、番茄牛腩半成品包
```

空气炸锅这类厨具升级要克制：

```text
只有当目标菜依赖低油酥脆口感，并且用户长期反馈怕油烟、怕麻烦或低洗锅时，才推荐空气炸锅。
```

否则优先给不购买的替代路线。

## 9. 开发检验台怎么看

打开：

```text
http://localhost:4174/dev.html
```

开发检验台里可以检查：

```text
Step 3：视觉识别原始返回
Step 4：晚餐规划输入与原始返回
Step 5：目标菜复刻输入与原始返回
```

重点确认：

```text
request.inventory 是否是人工确认后的库存
request.targetDish.text 是否是用户输入的目标菜
request.userContext.profile 是否携带了用户画像 traits
response.targetPlan.commerceCards 是否只在合理场景出现
```

## 10. 两条路线对比

| 路线 | 用户状态 | 点击按钮 | 核心价值 | 接口 |
|---|---|---|---|---|
| 共同前置 | 先看冰箱现实库存 | 识别冰箱 | 视觉识别 + 人工确认 | `/api/analyze-fridge` |
| 路线 A | 不知道吃什么 | 生成晚餐方案 | AI 直接规划今晚饭 | `/api/plan-dinner` |
| 路线 B | 已经想吃某道菜 | 判断复刻路线 | 判断能不能复刻、缺什么、怎么补 | `/api/plan-target-dish` |

