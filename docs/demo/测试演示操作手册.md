## 1. 当前 Demo 是什么

当前项目是「冰箱晚餐 Agent」本地 Demo。

核心链路：

```text
上传冰箱图片
  -> 视觉识别 Agent 识别可见食材
  -> 用户人工确认库存
  -> 晚餐规划 Agent 生成今晚方案
  -> 页面展示保底方案、进阶方案、缺料补买和安全提醒
```

当前不是 Python 项目，也不是 C++ 项目。主要代码是原生 JavaScript / Node.js：

- 后端 Agent：`demo/server.mjs`
- 展示页：`demo/index.html` + `demo/app.js`
- 开发检验台：`demo/dev.html` + `demo/dev.js`
- 样式：`demo/styles.css` + `demo/dev.css`

然后打开 `.env.local`，填入自己的中转站 API Key：

```env
OPENAI_API_KEY=你的中转站 API Key
OPENAI_BASE_URL=https://right.codes/codex/v1
MODEL_PROVIDER=rightcode_responses_stream
RIGHTCODE_CHAT_BASE_URL=https://www.right.codes/draw
RIGHTCODE_CHAT_MODEL=gemini-3.1-pro
OPENAI_MODEL=gpt-5.5
DISABLE_RESPONSE_STORAGE=true
```

注意：

- `.env.local` 只放在本地，不会上传 GitHub。
- `.env.local` 修改后必须重启服务才会生效。
- 不要把 API Key 写进文档、截图、提交信息或聊天记录。

## 5. 健康检查

服务启动后，可以打开：

```text
http://localhost:4174/api/health
```

正常应该看到类似：

```json
{
  "ok": true,
  "provider": "rightcode_responses_stream",
  "responsesBaseUrl": "https://right.codes/codex/v1",
  "model": "gpt-5.5",
  "hasApiKey": true,
  "disableResponseStorage": true
}
```

重点看：

- `ok` 应该是 `true`
- `provider` 应该是 `rightcode_responses_stream`
- `model` 应该是 `gpt-5.5`
- `hasApiKey` 应该是 `true`

如果 `hasApiKey:false`，说明 `.env.local` 没读到或没有填 Key。填完后重启服务。

## 6. 开发检验台测试流程

推荐先用开发检验台验链路：

```text
http://localhost:4174/dev.html
```

操作步骤：

1. 确认右上角显示：

```text
rightcode_responses_stream · gpt-5.5 · key:yes
```

2. 点击「选择冰箱图片」。

3. 推荐先选择项目里的样例图：

```text
assets/fridge-images/330d23dcca05ea8e54bbe6bace6677e7.png
```

或：

```text
assets/fridge-images/f63de1c0794c76a412b9f06f0d919044.png
```

如果上传手机拍摄的大图，前端会先在本地压缩到适合模型识别的尺寸，再发送给本地服务。这样可以降低中转站因为图片过大而返回 `fetch failed` 的概率。

4. 点击「调用视觉识别」。

5. 查看「视觉识别原始返回」。

正常情况下会看到完整 JSON，例如包含：

```text
番茄酱、饮料罐、百事可乐、鸡蛋、圆白菜、花菜、蘑菇、绿叶菜
```

具体结果每次可能略有变化，以原始 JSON 为准。

6. 查看「归一化库存与人工确认」。

这里是给用户确认的可用食材列表。可以取消勾选明显识别错的食材。

视觉识别成功后，页面会自动把本次结构化识别结果保存到当前演示用户的本地文件夹。后续如果现场网络慢或中转站不稳定，可以点击「加载上次识别」继续演示库存确认和晚餐规划。

缓存位置：

```text
data/local-users/<userId>/vision-cache.json
```

浏览器 `localStorage` 只作为兜底，它不是项目目录里的长期文件。不同演示用户之间的画像和冰箱缓存互相隔离。

7. 点击「调用晚餐规划」。

8. 查看「晚餐规划输入与原始返回」。

重点检查：

- `request.inventory` 是否就是人工确认后的库存。
- `response.plan` 是否给出合理的保底方案。
- 安全提醒是否保守，不要直接判断食材一定新鲜。

## 7. 展示界面演示流程

打开：

```text
http://localhost:4174/
```

现场演示推荐流程：

1. 简单介绍一句：

```text
这是一个从冰箱照片出发，帮用户决定今晚吃什么的视觉 Agent。
```

2. 点击上传区域，选择冰箱图片。

3. 点击「识别冰箱」。

4. 在「识别库存 / 3 秒确认可用食材」区域确认食材。

5. 取消勾选一两个不确定项，体现人工确认机制。

6. 点击「生成晚餐方案」。

7. 在「刷到想吃的」区域输入目标菜，或上传想复刻的菜图。

文字方式：

```text
我今晚想吃番茄牛腩
```

图片方式：

```text
上传目标菜图 -> 点击「识别目标菜」 -> 检查 AI 猜测的菜名和关键材料 -> 必要时手动修改输入框
```

确认目标菜文字无误后，点击「判断复刻路线」。

这一步用于展示新的抖音场景故事：

```text
刷到想吃的，拍下冰箱，AI 判断今晚能不能复刻。
```

目标菜结果不会展示可做指数或分数，避免现场解释评分算法。重点看：

- 能不能尽量复刻。
- 当前冰箱已有材料和关键缺口。
- 用户厨艺、时间和画像带来的难点提醒。
- 不购买的简化替代路线。
- 抖音商城 / 本地生活模拟补齐卡。

8. 展示右侧结果：

- 保底方案
- 进阶一点
- 缺料补买
- 外卖 / 速食兜底
- 目标菜复刻
- 安全提醒
- 商业延展

9. 强调产品价值：

```text
它不是只识别冰箱里有什么，而是把视觉库存、用户厨艺、时间和精力一起纳入决策，给出今晚最现实的一顿饭。
```

补充讲法：

```text
普通聊天机器人可以告诉你番茄牛腩怎么做，但这里会先看你家的冰箱、今晚时间和厨艺水平，判断现在能不能复刻；如果不能，就给你简化版本、明天补买路线和抖音生态里的模拟补齐卡。
```

## 8. 如何判断是不是模型真实结果

展示页左侧库存标题会标注来源。

如果是模型结果，会显示类似：

```text
模型识别 · gpt-5.5 · 12/12 已确认
```

如果加载的是上次成功识别缓存，会显示类似：

```text
上次模型结果 · gpt-5.5 · 12/12 已确认
```

如果是缓存样例，会显示：

```text
缓存样例 · 6/6 已确认
```

如果识别失败，会显示：

```text
识别失败 · 0/0 已确认
```

识别失败时，展示页不会再把缓存食材伪装成模型结果。要看具体错误，请打开：

```text
http://localhost:4174/dev.html
```

## 9. 常见问题

### 9.1 npm run dev 提示找不到 package.json

错误类似：

```text
npm error enoent Could not read package.json
```

原因是当前终端不在项目目录。先执行：

```bash
cd "/Users/wwl_mac/Desktop/2026春季第四学期/2026抖音ai创变者计划"
npm run dev
```

### 9.2 EADDRINUSE: address already in use

说明端口已经有服务在运行。可以直接打开对应端口使用。

查看 4174 端口：

```bash
lsof -nP -iTCP:4174 -sTCP:LISTEN
```

如果确认要停止旧服务：

```bash
kill <PID>
```

然后重启：

```bash
PORT=4174 npm run dev
```

### 9.3 页面提示 failed to fetch

常见原因：

- 没有启动 `npm run dev`
- 服务终端被关闭
- 用 `file://` 打开了 HTML
- 打开的是 4174，但服务跑在 4173
- `.env.local` 改完后没有重启服务
- 上传图片过大，中转站连接被断开

建议先检查：

```text
http://localhost:4174/api/health
```

如果健康检查正常，但识别接口返回：

```json
{
  "error": "fetch failed"
}
```

优先处理方式：

1. 先用 `assets/fridge-images` 里的样例图测试。
2. 如果样例图正常，说明服务和模型链路没问题，问题多半是上传图片太大或图片格式特殊。
3. 更新到最新版代码后，前端会自动压缩大图。
4. 修改了 `demo/server.mjs`、`demo/app.js` 或 `demo/dev.js` 后，需要重启 `npm run dev`。

### 9.4 hasApiKey 是 false

说明服务没有读到 API Key。

检查 `.env.local` 是否存在，且包含：

```env
OPENAI_API_KEY=你的中转站 API Key
```

填好后重启：

```bash
PORT=4174 npm run dev
```

### 9.5 模型返回和图片不太相符

这是当前 Demo 特意保留人工确认步骤的原因。

处理方式：

1. 到开发检验台看原始 JSON。
2. 在库存列表取消勾选错误食材。
3. 再生成晚餐方案。
4. 记录明显误识别案例，后续优化提示词和样例图。
