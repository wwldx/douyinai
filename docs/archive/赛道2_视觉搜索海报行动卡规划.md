# 赛道 2：视觉搜索海报行动卡规划

更新日期：2026-05-23  
赛道：视觉搜索：视觉 + 语音，所见即所想  
默认模型策略：优先调用 GPT / Claude 高阶视觉模型，接口层保留可切换能力  
当前定位：校园活动海报视觉理解 Agent，从“看见海报”到“采取行动”

## 1. 当前共识

赛道 2 不应该做成“识别这是什么”的单点功能。它需要把视觉理解结果继续转成用户行动。

当前最稳方向仍然是活动海报视觉助手，而不是自拍分析或菜品分析。

选择原因：

- 海报 OCR、版面理解、信息抽取是高阶多模态模型比较擅长的任务。
- 结果可以结构化核对，评委容易判断正确性。
- 输出可以自然延展到推荐、日程、转发文案和追问。
- 现场可以准备高质量样例和缓存结果，稳定性更高。
- 相比自拍和菜品，隐私、伦理和准确性质疑更少。

## 2. 一句话定位

拍一张校园活动海报，AI 自动读懂活动信息，并根据用户身份生成“值不值得去、怎么去、怎么分享”的行动卡片。

候选产品名：

- 海报速读行动卡
- Campus Poster Agent
- 活动海报 AI 行动助手

建议最终表达：

> 它不是 OCR，而是把一张海报变成摘要、判断、日程和转发行动。

## 3. 目标用户与场景

目标用户：

- 路过公告栏、食堂门口、社团摊位的学生。
- 在群聊或朋友圈刷到活动海报但懒得细读的人。
- 游园会现场评委、游客和其他选手。

触发时刻：

- 用户看到一张信息密度很高的活动海报。
- 用户只愿意花 10 到 30 秒判断是否值得参加。
- 用户需要把活动快速发给同学、加入日程或现场报名。

## 4. 核心体验闭环

主流程：

1. 用户上传或拍摄一张活动海报。
2. 用户选择一个轻量身份标签：
   - 技术向
   - 社交向
   - 竞赛向
   - 薅福利
   - 时间紧
3. GPT / Claude 视觉模型读取海报。
4. 系统输出结构化活动信息：
   - 活动名称
   - 时间
   - 地点
   - 报名方式
   - 主办方
   - 亮点
   - 不确定字段
5. AI 根据身份标签输出：
   - 推荐指数
   - 适合原因
   - 不适合或注意事项
   - 到场准备
6. 用户生成：
   - 日程提醒文案
   - 转发给朋友的话
   - 可分享卡片
   - 可追问问题

30 秒演示路径：

1. 点击预置海报。
2. 选择“技术向”。
3. 展示模型识别出的时间、地点、报名方式。
4. 展示推荐指数和适合原因。
5. 点击生成转发文案。
6. 展示可复制行动卡。

## 5. 为什么不优先做自拍或菜品

| 方向 | 主要问题 | 结论 |
|---|---|---|
| 自拍分析 | 容易涉及颜值、年龄、情绪、健康、隐私判断，表达边界难控制 | 不建议做主线 |
| 菜品分析 | 菜名可识别，但热量、营养、克重容易不准，现场容易被质疑 | 可作为未来轻建议扩展 |
| 物品平替 | 需要商品库或搜索链路，否则像通用图像描述 | 当前不做主线 |
| 板书/题目讲解 | 技术感强，但容易撞 OCR/解题工具，且幻觉风险高 | 可作为备选 |
| 活动海报 | 识别可核对，行动链路自然，现场样例容易准备 | 主推 |

## 6. 模型调用策略

默认直接使用最强 GPT / Claude 视觉模型，不以低成本模型作为主线。

建议策略：

| 用途 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 海报视觉理解 | GPT 高阶视觉模型 | Claude 高阶视觉模型 | 看实际 OCR 和版面理解稳定性 |
| 复杂长海报解释 | Claude 高阶视觉模型 | GPT 高阶视觉模型 | 长文本解释和推荐理由可 AB 测 |
| 结构化 JSON 生成 | GPT 高阶模型 | Claude 高阶模型 | 严格要求 JSON schema |
| 现场兜底 | 本地缓存 JSON | 预置样例结果 | 网络或接口失败时直接展示 |

工程上做模型适配层：

```text
VisionProvider
  - provider: "openai" | "anthropic" | "mock"
  - model: configurable
  - analyzePoster(image, persona)
```

模型名放后端配置或环境变量，不写死在前端。

## 7. 输出 JSON 结构

模型必须输出固定 JSON，禁止直接把大段 Markdown 交给前端。

```json
{
  "poster": {
    "title": "活动名称",
    "category": "讲座|比赛|社团|游园|招聘|其他",
    "time": "时间，未识别则写未识别",
    "location": "地点，未识别则写未识别",
    "organizer": "主办方，未识别则写未识别",
    "signup": "报名方式，未识别则写未识别",
    "audience": "面向人群，未识别则写未识别",
    "highlights": ["亮点 1", "亮点 2"],
    "uncertainFields": ["不确定字段"]
  },
  "personalized": {
    "persona": "技术向",
    "score": 86,
    "verdict": "值得去",
    "reasons": ["原因 1", "原因 2"],
    "risks": ["注意事项 1"],
    "prep": ["准备事项 1", "准备事项 2"]
  },
  "actions": {
    "calendarText": "日程提醒文案",
    "shareText": "转发给朋友的短文案",
    "nextStep": "下一步行动",
    "questions": ["我需要带什么？", "适合新手吗？"]
  }
}
```

## 8. Prompt 草案

系统提示词：

```text
你是校园活动海报视觉理解助手。你需要从用户上传的活动海报中提取结构化信息，并根据用户身份标签生成行动建议。

要求：
1. 优先识别活动名称、时间、地点、报名方式、主办方、面向人群和关键亮点。
2. 不确定的信息必须标注为“未识别”，不要编造。
3. 如果海报包含二维码但无法读取，写“二维码存在但内容未识别”。
4. 个性化建议必须结合用户身份标签。
5. 输出必须是 JSON，不要输出 Markdown。
6. 结果要服务于用户下一步行动，而不是只描述图片。
```

用户提示词模板：

```text
用户身份标签：{persona}

请分析这张校园活动海报，输出活动摘要、推荐指数、适合原因、注意事项、准备事项、日程提醒文案和转发给朋友的短文案。
```

## 9. 页面结构

建议单页应用：

| 区域 | 功能 | 优先级 |
|---|---|---|
| 顶部状态栏 | 产品名、赛道、当前模型状态 | 中 |
| 海报输入区 | 上传图片、拍照、选择预置样例 | 高 |
| 身份标签区 | 技术向、社交向、竞赛向、薅福利、时间紧 | 高 |
| 原图预览区 | 保留原图，方便核对识别结果 | 高 |
| AI 摘要区 | 活动名、时间、地点、报名方式、亮点 | 高 |
| 个性化建议区 | 推荐指数、适合原因、风险、准备事项 | 高 |
| 行动生成区 | 日程提醒、转发文案、分享卡 | 高 |
| 兜底状态 | 显示缓存结果和模型失败提示 | 高 |

## 10. 样例准备

至少准备 5 张图片：

| 样例 | 用途 |
|---|---|
| 当前比赛海报 | 和现场强相关，评委容易理解 |
| 学术讲座海报 | 测试时间地点和主办方抽取 |
| 社团活动海报 | 测试传播性和普通用户价值 |
| 招新/报名类海报 | 测试报名方式和二维码说明 |
| 信息很密的长图海报 | 测试复杂版面鲁棒性 |

每张图都准备一份缓存 JSON。现场演示优先用预置图片，现场拍摄作为加分演示。

## 11. MVP 开发拆分

第一阶段：静态闭环

- 复用现有 Web Demo。
- 增加 3 到 5 张预置海报。
- 准备缓存 JSON。
- 完成身份标签切换。
- 完成摘要、推荐、行动卡渲染。

第二阶段：接入 GPT / Claude 视觉模型

- 写后端 `/api/analyze-poster`。
- 支持图片上传。
- 调用视觉模型。
- 解析并校验 JSON。
- 失败时回退缓存结果。

第三阶段：现场增强

- 增加复制日程提醒。
- 增加生成分享卡。
- 增加“追问”按钮。
- 准备演示录屏。
- 做移动端适配。

## 12. 评测方法

在确定主模型前，用同一批图片做小规模 AB 测试。

评分维度：

| 维度 | 评分标准 |
|---|---|
| OCR 准确度 | 时间、地点、标题、报名方式是否正确 |
| 结构化稳定性 | 是否稳定返回合法 JSON |
| 不确定性处理 | 看不清时是否标注未识别，而不是编造 |
| 推荐质量 | 是否真的结合身份标签 |
| 延迟 | 是否能在现场接受范围内返回 |

建议记录表：

| 图片 | GPT 结果 | Claude 结果 | 结论 |
|---|---|---|---|
| 比赛海报 | 待测 | 待测 | 待定 |
| 学术讲座 | 待测 | 待测 | 待定 |
| 社团活动 | 待测 | 待测 | 待定 |
| 招新海报 | 待测 | 待测 | 待定 |
| 长图海报 | 待测 | 待测 | 待定 |

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型 OCR 漏字 | 信息错误 | 保留原图核对，不确定字段标未识别 |
| JSON 输出不合法 | 前端渲染失败 | schema 校验 + 自动重试 + 缓存兜底 |
| 现场网络不稳 | Demo 卡住 | 预置样例和录屏 |
| 被认为只是 OCR | 创新性不足 | 强调个性化判断和行动生成 |
| 真实拍摄光线差 | 识别不稳 | 现场拍摄只做加分，主演示用样例 |

## 14. 评分点对齐

| 评分关注 | 对齐方式 |
|---|---|
| 用户价值 | 帮学生 30 秒内判断活动值不值得参加 |
| AI 能力结合 | 视觉理解结果直接驱动推荐、日程和分享 |
| 体验完整性 | 上传海报 -> 识别 -> 个性化判断 -> 行动卡 |
| 创新性 | 从 OCR 走到决策和下一步行动 |
| 现场表现 | 可用真实海报试玩，也有缓存兜底 |

## 15. 现场讲解脚本

60 秒版：

```text
我们做的是海报速读行动卡，选择视觉搜索赛道。

大学里每天都有很多活动海报，但大多数人只扫一眼，很难马上判断是否值得参加。我们的 Demo 让用户上传一张海报，再选择自己的身份，比如技术向、社交向或时间紧。

AI 会先从图片里提取活动名称、时间、地点和报名方式，再根据用户身份给出推荐指数、适合原因和准备事项。最后它还能生成日程提醒和转发给朋友的话。

所以它不是单纯 OCR，而是把“看到一张海报”推进到“我知道要不要去，以及下一步怎么做”。
```

## 16. 最终建议

赛道 2 主线继续推进“活动海报视觉助手”。这条线最适合用强视觉模型打出 AI 能力，也最容易做成现场可体验闭环。

最小可行目标：

- 3 到 5 张预置海报。
- GPT / Claude 实时识别至少一张海报。
- 每张图有缓存 JSON。
- 支持身份标签切换。
- 输出摘要、推荐、日程、转发文案。
- 模型失败时 Demo 不崩。
