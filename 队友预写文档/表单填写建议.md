## 8. 项目介绍文档链接

填写飞书文档分享链接：`【飞书文档链接】`

如果需要粘贴文档内容，可复用以下版本：

厨房小助手是一款面向厨艺新手、下班后精力有限、冰箱有货但不知道吃什么的用户的视觉搜索 AI Agent。用户只需要上传一张冰箱照片，系统会识别可见食材、速食、包装和不确定项，再让用户勾选确认库存，最后结合餐次、可用时间、精力状态、厨艺水平和口味偏好，生成今晚最现实的一顿饭方案。

它解决的不是单纯「识别这是什么」的问题，而是日常高频的「我现在到底吃什么」。普通菜谱工具要求用户先想好菜名和食材，普通识别工具停留在图片描述；厨房小助手把视觉理解和行动规划连接起来，从真实冰箱出发，给出保底菜、进阶菜、缺料补买、安全提醒和必要兜底方案。

当前 Demo 已实现三步体验：上传冰箱照片、确认识别出的食材、生成晚餐方案。若用户刷到想吃的菜，也可以上传目标菜图或输入菜名，系统会先识别菜名和关键材料，再结合家里库存判断今晚能不能照着做，缺什么材料，以及是否适合改成简化版本。结果页还加入了「加入模拟购物车，去抖音商城看看」和「拍成品，生成抖音生活记录」入口，用来表达从内容种草、冰箱判断、材料补齐到饭后记录的抖音生态闭环。

实现上，项目采用 Vite + React 展示端和 Node.js 本地服务。后端提供轻量 Agent API，包括冰箱视觉识别、目标菜图识别、晚餐规划和目标菜复刻规划。模型接口使用 OpenAI 兼容 Responses API，并通过 JSON Schema 输出结构化结果，前端不解析自由文本。为了保证现场稳定性，项目准备了演示用户、视觉预分析缓存和上次识别缓存；模型超时或失败时可以明确提示并兜底，不会把缓存伪装成实时模型结果。

核心创新点包括：第一，从「识别物品」升级为「完成一餐决策」，让视觉搜索直接驱动行动；第二，设计用户确认库存步骤，正视多模态识别的不确定性；第三，结合用户时间、厨艺、精力和偏好，不做泛泛菜谱推荐；第四，将刷到美食内容后的「想照着做」与现实冰箱库存连接起来，形成更贴近抖音场景的体验链路；第五，商业建议保持克制，只在缺料、工具缺口或兜底场景自然出现。

## 9. 体验流程

可直接填写：

1. 打开展示端页面，进入厨房小助手。
2. 上传一张冰箱照片，或选择项目提供的演示冰箱样例。
3. 选择餐次、可用时间和当前状态，例如晚餐、25 分钟、今天很累。
4. 点击识别冰箱，等待 AI 识别可见食材、速食、饮料和不确定物品。
5. 查看识别出的库存列表，取消勾选明显错误或暂时不想使用的食材。
6. 如果不知道吃什么，选择「帮我决定」，系统会根据确认后的库存和用户状态生成这一餐方案，包括保底菜、进阶菜、步骤、缺料补买和安全提醒。
7. 如果刷到想吃的菜，选择「我有想吃的」，可以输入菜名或上传目标菜图片。系统会先识别目标菜，再让用户确认菜名和补充约束。
8. 点击判断复刻路线，系统会说明家里哪些材料可用、还差什么、今晚适合做原版还是简化版，并给出执行步骤。
9. 结果页可点击「重新规划」回到第二步，保留已识别冰箱和确认库存；也可点击「换一张冰箱重新看」重新开始。
10. 当缺关键材料时，可查看模拟的抖音商城补买卡；做完饭后可点击「拍成品，发抖音」入口，表达饭后生活记录闭环。

## 13. 补充回答

可直接填写：

厨房小助手当前主线聚焦「冰箱晚餐 Agent」。我们保留了海报方向的早期探索，但最终选择了更具体、更容易现场验证的高频生活场景：用户打开冰箱，不知道今晚吃什么。项目强调 AI 不是只识别图片，而是把视觉结果转化为可执行的一餐决策。

在安全边界上，系统不会直接判断食材是否过期、肉类是否安全或剩菜是否还能吃；这类信息会提醒用户自行确认。不确定食材不会被硬编进推荐，而是通过人工勾选确认进入后续规划。

在抖音场景上，项目加入了「刷到想吃的菜 -> 拍冰箱 -> 判断今晚能不能照着做 -> 缺料时模拟补买 -> 做完生成生活记录入口」的闭环，使视觉搜索与内容种草、交易补齐和生活记录自然衔接。
