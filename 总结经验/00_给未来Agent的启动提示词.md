# 给未来 Agent 的启动提示词

下面这段可以在以后做新 Agent 项目时，直接复制给 Codex、Claude Code、Cursor Agent 或其他 AI 编程助手。它的作用是让 Agent 先继承本次比赛形成的工作方法。

## 通用启动提示词

```text
你现在要协助我从 0 到 1 做一个 AI Agent 项目。请先阅读当前项目里的 `总结经验/` 文件夹，尤其是：

- `README.md`
- `01_比赛型Agent项目从0到1流程.md`
- `02_选题收敛与评分对齐.md`
- `03_Agent_MVP架构与数据合约.md`
- `04_开发检验台与调试闭环.md`
- `05_模型不稳定与现场兜底.md`
- `06_用户体验与话术原则.md`
- `AI_Agent情景化Demo展示工作流.md`
- `07_路演提交与现场作战清单.md`

阅读后请先不要急着写代码。先帮我做四件事：

1. 把当前项目想法压成一句话价值：
   当 [目标用户] 在 [具体场景] 遇到 [痛点] 时，
   这个 Agent 通过 [核心 AI 能力]，
   帮助用户完成 [现实结果]。

2. 判断这个项目是否适合做成比赛 / 课程 / 作品集 Demo：
   - 场景是否足够具体？
   - AI 是否参与关键判断？
   - 用户端是否能 30-60 秒讲清楚？
   - 是否能做开发检验台证明不是写死？
   - 模型失败时是否有兜底？

3. 给出 MVP 主路径：
   - 用户只需要做哪 1-3 个动作？
   - Agent 背后完成哪 2-5 个判断？
   - 最终输出是什么现实可执行结果？

4. 给出建议文件结构和第一轮任务清单：
   - 用户端页面
   - Agent API
   - JSON schema
   - 开发检验台
   - 缓存兜底
   - Demo 文档和讲稿

工作原则：

- 先做一个具体闭环，不做泛 AI 助手。
- 先让用户端可演示，再补复杂架构。
- 模型输出必须结构化。
- 多模态识别或高不确定结果必须有人确认。
- 前台隐藏内部细节，后台展示输入输出。
- 每次重要产品/技术决策都写进项目文档。
- 不要提交 API Key、真实隐私数据或本地缓存。
```

## 比赛冲刺版提示词

如果比赛只剩一天，可以用这个更强约束版本：

```text
我们现在是比赛冲刺状态，请用“现场稳定优先”的方式协助我。

请先阅读 `总结经验/` 文件夹，然后按下面优先级推进：

1. 30 秒内能讲清楚用户价值。
2. 1 分钟内能跑通一个主路径。
3. 有开发检验台证明链路不是写死。
4. 模型失败时有缓存或录屏兜底。
5. 提交材料和路演讲稿能对齐评分点。

不要做这些事：

- 不要引入重框架来证明自己像 Agent。
- 不要在最后一天大改架构。
- 不要把语音、长期记忆、真实下单等不稳定功能放进主流程。
- 不要让用户端展示模型名、JSON、错误栈或 API Key。

请先输出：

- 今日必须完成清单
- 可以砍掉的功能
- 必须准备的兜底素材
- 路演讲解顺序
- 风险最高的 3 个点和解决方案
```

## 项目复盘版提示词

赛后整理经验时，可以复制：

```text
请帮我基于当前项目做一次赛后复盘，不要只写感想，要提炼成下次可复用的方法。

请按这些部分输出：

1. 项目最终做成了什么。
2. 哪些决策是正确的，为什么。
3. 哪些问题暴露得最明显。
4. 如果重做一次，前 6 小时应该怎么安排。
5. 哪些代码、文档、模板可以复用。
6. 哪些功能看起来高级但不适合 MVP。
7. 下一次 Agent 项目应该默认采用哪些规范。
8. 需要补充到 `总结经验/` 文件夹的内容。
```
