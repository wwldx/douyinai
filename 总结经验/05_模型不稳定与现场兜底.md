# 模型不稳定与现场兜底

现场 Demo 失败，往往不是因为产品想法不行，而是因为模型慢、接口挂、图片识别错、浏览器权限卡住、端口被占用。比赛型 Agent 项目必须把“失败会发生”当作默认前提。

## 1. 兜底不是造假

兜底的边界是：

```text
用户端保证体验连续
开发台标明真实来源
不把缓存伪装成模型实时成功
```

本次项目的正确方向是：

```text
模型优先
超时或失败再用缓存
开发台展示 source
展示端不暴露内部细节
```

这既保证现场可演示，也保留技术诚实。

## 2. 常见失败类型

| 失败 | 表现 | 兜底 |
|---|---|---|
| 无 API Key | 接口直接失败 | 本地缓存样例 |
| 网络慢 | loading 很久 | 阶段提示、超时缓存 |
| 模型输出非 JSON | 解析失败 | schema retry 或 fallback |
| 图片识别错 | 菜名/食材错误 | 用户确认和手动修改 |
| 用户输入奇怪 | 规划跑偏 | 输入校验和保守回复 |
| 浏览器录音权限 | 语音不可用 | 文本输入 |
| 端口占用 | 服务启动失败 | 查 PID、换端口 |
| 前端状态污染 | 改文字仍用旧图 | 明确优先级和状态重置 |

## 3. 四层兜底体系

### 3.1 产品层兜底

给用户可理解的选择：

```text
继续等待
加载上次结果
手动修改识别内容
换一张图
先用简化方案
```

不要只显示：

```text
Error: request failed
```

### 3.2 数据层兜底

准备固定样例：

```text
demo-cache/
sample-inputs/
sample-outputs/
```

样例要覆盖主场景，不要只准备一个。

本次项目可复用样例类型：

```text
普通冰箱
深夜简餐
想做目标菜但缺主料
模型识别不确定
```

### 3.3 交互层兜底

让用户能纠错：

```text
确认库存
手动改菜名
选择餐次和时间
选择帮我决定 / 我有想吃的
重新规划回到第二步
```

原则：

> AI 负责降低输入成本，用户负责确认关键事实。

### 3.4 演示层兜底

比赛现场必须有：

```text
完整备用录屏
固定演示图片
固定输入文字
本地缓存结果
离线讲稿
```

如果现场网络挂了，仍然能讲清楚项目。

## 4. 等待体验

等待状态不能只是转圈。

推荐显示：

```text
当前阶段
已用秒数
下一步可能发生什么
超时后的选择
```

例子：

```text
正在发送图片，已用 3 秒。
视觉模型还在识别，已用 12 秒。
如果超过 45 秒，可以继续等待或加载上次识别结果。
```

等待文案也要生活化：

| 技术话术 | 用户话术 |
|---|---|
| 正在调用多模态模型 | 正在看这张图里有什么 |
| 正在执行规划 Agent | 正在帮你判断今晚怎么吃 |
| schema parse failed | 模型返回格式不太稳定，请重试或加载缓存 |

## 5. 超时策略

建议设置两类超时：

```text
软超时：提示用户模型较慢，但继续等待。
硬超时：返回缓存或错误。
```

比赛现场可以更激进：

```text
4-8 秒命中演示缓存，但开发台标注 model-timeout-cache。
```

公开产品则应更谨慎：

```text
继续等待更长时间，或明确询问用户是否使用上次结果。
```

## 6. 缓存命中策略

不要因为文件名命中就秒回，否则现场显得假。

推荐：

```text
先发模型请求
超过阈值且有缓存时，再返回缓存
模型错误且有缓存时，再返回缓存
```

缓存匹配可以基于：

```text
文件名
样例 ID
图片 hash
用户 ID + 最近一次成功识别
```

开发台必须显示：

```text
matchedBy
cacheKey
cachedAt
source
```

## 7. 语音、视频、真实下单等高风险功能

这些功能看起来加分，但现场风险很高：

```text
语音权限
ASR provider
视频生成时间
真实支付/下单
第三方登录
地图定位
摄像头权限
```

比赛主流程原则：

```text
不稳定功能做成实验入口，不做主演示路径。
```

本次项目里，语音输入保留为实验链路是正确决策。

## 8. 现场前兜底清单

比赛前最后检查：

```text
1. 无网络时能不能讲？
2. 无 API Key 时页面是否能展示样例？
3. 模型超时时是否有提示？
4. 开发台是否显示 source？
5. 备用录屏是否能播放？
6. 固定样例图片路径是否存在？
7. 端口被占用时如何处理？
8. 页面刷新后是否能继续演示？
9. 用户端是否隐藏错误栈？
10. 是否没有 API Key 泄露？
```

## 9. 最重要的复用句

> 现场稳定性不是最后补的保险，而是 Agent 产品设计的一部分。
