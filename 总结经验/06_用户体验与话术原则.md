# 用户体验与话术原则

AI Agent 项目很容易陷入“技术很强，但用户听不懂”。这份文档总结本次项目里关于用户端设计、生活化话术、人机协作和结果页表达的经验。

## 1. 用户端不是后台

用户端应该只展示用户做决策需要的信息。

不展示：

```text
provider
model
confidence
raw JSON
schema
cache path
错误栈
内部画像字段
```

可以展示：

```text
用户上传的内容
用户需要确认的事实
用户选择的目标
结果方案
缺什么
下一步怎么做
必要提醒
```

## 2. 少说技术词，多说生活话

本次项目曾出现一些不自然话术，比如：

```text
关键缺口
复刻目标菜
待确认目标菜
模型结果
鸡腿肉是复刻黄焖鸡的关键缺口
```

更好的表达：

```text
还差鸡腿肉和土豆
想照着做这道菜
看看家里够不够做
这张图像是黄焖鸡，你也可以改
做黄焖鸡少不了鸡腿肉，家里没有的话味道会差不少
```

## 3. 话术替换表

| 技术感表达 | 生活化表达 |
|---|---|
| 复刻 | 照着做 / 做个接近的版本 |
| 关键缺口 | 还差 / 少了这几样 |
| 目标菜 | 想吃的菜 |
| 可做指数 | 家里够不够做 |
| 多模态识别 | 看看图里有什么 |
| Agent 规划 | 帮你判断下一步 |
| 用户画像 | 按你的时间和习惯 |
| 商业转化 | 顺手补点材料 |
| 内容回流 | 做完拍一下，记录生活 |
| fallback | 先用上次结果 / 先给你一个稳妥方案 |

## 4. 结果页要给行动，不给作文

不推荐结果页：

```text
长篇解释为什么这道菜很好吃，以及泛泛的营养建议。
```

推荐结构：

```text
一句判断
已有
还差
今晚怎么做
难点提醒
顺手补点材料
做完记录
```

用户最需要的是：

```text
我现在该干什么？
有没有坑？
缺什么？
可不可以先简化？
```

## 5. 人机协作原则

AI 不应该假装全知。

这些必须交给用户确认：

```text
食材是否新鲜
肉类是否安全
是否真的有某样食材
用户现在愿不愿意做复杂菜
用户想吃的菜名
用户的忌口和过敏
```

AI 可以做：

```text
降低录入成本
列出候选项
提醒不确定
基于约束规划
给出替代方案
把下一步变简单
```

一句话：

> AI 负责看清可能性，用户确认现实条件。

## 6. 不要把推断说成事实

不推荐：

```text
AI 判断你今晚很累。
你是夜猫子。
你不爱做饭。
```

推荐：

```text
如果你今天只想花 20 分钟，可以走快手路线。
你最近深夜用餐请求较多，所以这里优先给少油热食。
你选择了“不想洗锅”，所以推荐一锅完成。
```

原则：

```text
用户显式选择可以直接说。
系统推断要中性表达。
高风险健康信息不能自动推断。
```

## 7. CTA 要服务当前任务

商业入口、分享入口、记录入口都不要硬塞。

本次项目里比较自然的 CTA：

```text
还差材料 -> 加入购物车，去抖音商城看看
做完饭 -> 拍成品，发抖音记录生活
```

因为它们顺着用户任务发生。

不自然的 CTA：

```text
刚上传冰箱就推荐一堆商品。
用户想做饭却大力推荐外卖。
结果还没出来就引导发视频。
```

## 8. 页面流程原则

### 8.1 不要把用户带回起点

本次修过的问题：

```text
第三页点击重新规划，直接回第一步。
```

更符合用户心理：

```text
重新规划 -> 回第二步，保留冰箱识别和库存确认。
换一张冰箱 -> 回第一步并清空图片。
```

原则：

> 用户只想改决策时，不要让他重做输入。

### 8.2 识别后要给编辑机会

目标菜图上传后，不应该直接规划。

更好的流程：

```text
上传目标菜图
-> AI 猜菜名
-> 写入文本框
-> 用户修改或补充条件
-> 用户点击生成
```

这条原则可迁移：

```text
OCR 后让用户改文字
语音转写后让用户改文本
图片识别后让用户改标签
画像推断后让用户选择是否采用
```

## 9. 视觉体验原则

本次提到的食材图标也是可复用经验：

```text
识别结果如果全是文字，会显得像后台列表。
用小图标、分组、状态、颜色和按钮，可以让用户更快理解。
```

但注意：

- 图标要服务识别，不要装饰过度。
- 按钮文字要短。
- 移动端不能挤。
- 不要把信息全塞卡片里。
- 结果页重点要突出“今晚怎么做”。

## 10. 用户端检查清单

```text
1. 第一屏是否直接进入可操作体验？
2. 用户是否知道下一步点哪里？
3. 模型等待是否有阶段提示？
4. 识别结果是否可修改？
5. 结果页是否给行动路线？
6. 文案是否像人话？
7. 是否避免“复刻”“关键缺口”等生硬词？
8. 是否隐藏后台字段？
9. 是否有返回上一关键步骤的路径？
10. 商业和分享 CTA 是否自然？
```
