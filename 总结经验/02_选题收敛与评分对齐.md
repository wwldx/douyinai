# 选题收敛与评分对齐

比赛型 Agent 项目的成败，很多时候在写代码前就已经决定了一半。选题如果太泛、太难演示、和评分点脱节，后面再努力也很难救。

## 1. 好选题的五个标准

一个适合比赛的 Agent 选题，最好同时满足：

```text
高频真实
场景具体
AI 必要
结果可见
现场稳定
```

解释：

| 标准 | 问题 | 好答案 |
|---|---|---|
| 高频真实 | 用户真的会遇到吗 | 每天/每周都会发生 |
| 场景具体 | 30 秒能讲清楚吗 | 某类人在某个时刻卡住 |
| AI 必要 | 不用 AI 能不能一样做 | AI 负责理解、判断、规划或生成 |
| 结果可见 | 展示时能看到变化吗 | 从输入到行动方案 |
| 现场稳定 | 能不能准备样例和兜底 | 有缓存、录屏、手动修正 |

## 2. 选题评分矩阵

新想法可以按 1-5 分打分：

| 维度 | 说明 | 分数 |
|---|---|---:|
| 用户痛点强度 | 是否真实、具体、高频 |  |
| AI 不可替代性 | 是否需要视觉、语言、推理、规划 |  |
| 演示清晰度 | 30 秒能否讲明白 |  |
| 交互完整度 | 是否有输入、判断、输出、行动 |  |
| 现场稳定性 | 是否能准备缓存和兜底 |  |
| 差异化 | 是否不像普通 Chatbot |  |
| 生态连接 | 是否能接内容、交易、分享、协作 |  |
| 开发可控性 | 当前时间和能力能否做完 |  |

建议：

```text
总分 32 以上：适合比赛主线
总分 26-31：可以做，但要继续收窄
总分 20-25：风险较高，适合备选
总分 20 以下：不要作为主线
```

## 3. 红旗信号

看到这些表达，要警惕选题太泛：

```text
万能
全场景
一站式
智能生活助手
个人 AI 管家
自动帮你解决所有问题
```

不是不能做大，而是 MVP 必须从一个具体场景切入。

更好的改写：

| 太泛 | 收窄 |
|---|---|
| 智能饮食助手 | 晚上打开冰箱不知道吃什么 |
| 学习助手 | 考前三天不知道先复习哪章 |
| 求职助手 | 不知道怎么把项目经历写进简历 |
| 办公助手 | 一堆票据不知道怎么报销 |
| 旅行助手 | 周末临时出门不知道怎么安排半日路线 |

## 4. 评分点反推法

比赛项目要主动对齐评分，而不是做完再解释。

通用评分项通常包括：

```text
创新性
AI 能力结合
用户价值
体验完整度
技术实现
商业或生态潜力
现场表达
```

每个评分点都要有可展示证据：

| 评分点 | 不够好的说法 | 更好的证据 |
|---|---|---|
| 创新性 | 我们用了 Agent | 从内容种草连接到现实库存和行动 |
| AI 能力 | 用了大模型 | 视觉识别、结构化规划、用户画像共同决策 |
| 用户价值 | 提升效率 | 用户从“不知道吃什么”到“今晚照着做” |
| 完整体验 | 有页面 | 输入、确认、规划、补货、记录闭环 |
| 技术实现 | 调了 API | 开发检验台展示输入输出和兜底 |
| 商业潜力 | 可以变现 | 缺材料时自然连接商城或本地生活 |

## 5. 选题验证问题

确定主线前，至少问自己十个问题：

```text
1. 这个用户是谁？能不能描述成一个具体人？
2. 他什么时候打开这个产品？
3. 他打开前正在发愁什么？
4. 他愿意提供什么输入？
5. AI 第一眼看到什么？
6. AI 必须判断什么？
7. 哪一步必须让用户确认？
8. 最终输出能不能让用户立刻行动？
9. 现场失败时怎么兜底？
10. 评委看完能不能复述一句话？
```

如果第 10 个问题答不好，展示风险很高。

## 6. 本次比赛的可复用选题经验

### 6.1 场景要有“画面”

“打开冰箱发愁”比“饮食决策优化”更有画面。

以后选题也要优先找有画面的场景：

```text
看着空白简历发呆
打开论文不知道读哪里
对着一堆发票崩溃
打开衣柜不知道穿什么
看着错题不知道怎么复习
```

画面感越强，情景视频越容易做，观众越容易记住。

### 6.2 AI 要做“判断”，不是只做“描述”

只识别冰箱里有什么，不够。

更强的是：

```text
这些东西今晚能做什么？
刷到这道菜，家里够不够做？
缺的东西是否值得补？
用户只有 25 分钟，哪条路线现实？
```

可复用判断：

> 如果 AI 输出只是“看到了什么”，还不够 Agent；如果它能基于约束决定“下一步怎么做”，才更像 Agent。

### 6.3 商业闭环要自然，不硬推

本次“缺材料 -> 模拟购物车 -> 抖音商城”是自然闭环，因为它服务当下问题。

不推荐：

```text
用户只是想吃饭，页面突然塞一堆广告。
```

推荐：

```text
因为还差鸡腿肉和土豆，所以提供顺手补点材料入口。
```

原则：

> 商业化应该出现在用户需要下一步行动的地方。
