# 总结经验：AI Agent 项目复用资料包

这个文件夹用于沉淀本次抖音 AI 创变者计划做「厨房小助手 / 冰箱晚餐 Agent」时形成的方法论。目标不是复盘某一次比赛细节，而是做成以后任何 Agent 项目都能直接参考的“启动资料包”。

以后开启新 Agent 项目时，可以先把整个 `总结经验/` 文件夹交给新的 AI 编程助手阅读，再让它结合新项目需求执行。

## 这次比赛最值得复用的核心经验

一句话：

> Agent 项目不要从“模型能做什么”开始，而要从“用户卡在哪个真实时刻”开始；不要只做功能页面，要同时准备用户端、开发检验台和现场兜底。

拆开看是八条：

1. 选题先收窄到一个真实高频时刻，而不是泛 AI 助手。
2. MVP 先做闭环，再做完整架构。
3. Agent 必须参与关键判断，不能只是把模型输出包装成页面。
4. 多模态识别、偏好、安全类结果要保留用户确认。
5. 前端展示要生活化，后台检验台要工程化。
6. 模型输出必须结构化，接口失败必须有兜底。
7. 比赛讲解要先讲人和场景，再讲技术。
8. 赛后必须把选题、架构、话术、失败经验写成文档，下次才能复利。

## 下次开新项目时怎么用

建议新项目第一小时这样做：

```text
1. 让 Agent 阅读本目录 README 和 00 启动提示词。
2. 用 02 文件里的评分矩阵筛选 2-3 个方向。
3. 用 01 文件里的流程确定 MVP 闭环。
4. 用 03 文件设计 Agent 输入输出和 JSON 合约。
5. 同步规划 04 开发检验台和 05 兜底策略。
6. 最后用 AI_Agent情景化Demo展示工作流.md 做演示脚本。
```

不要等功能写完才想怎么展示。展示方式应该从第一天就反推产品边界。

## 文件维护规则

- 新比赛、新项目、新失败经验，都应该补充进这个文件夹。
- 不要把具体 API Key、账号、隐私图片写进这里。
- 可以保留具体案例，但要提炼成可迁移原则。
- 如果某条经验只适用于「厨房小助手」，要明确标注；如果可以通用，要改写成模板。
- 每次比赛结束后，至少更新 `08_赛后复盘模板.md` 对应的一份复盘。
